# npm-offline-mirror

> A tiny Docker-based **npm registry mirror** (powered by [Verdaccio](https://verdaccio.org)) pre-loaded with the most popular frontend, backend and tooling packages, so you can keep developing JavaScript / Node.js projects for days or weeks **without internet access**.

## How it works

```
 online                                     offline
 ──────                                     ───────
 npm / pnpm / yarn ─► Verdaccio ─► npmjs    npm / pnpm / yarn ─► Verdaccio (cache only)
                          │
                      cache volume  ◄── exported with `make export`, restored with `make import`
```

* One container, one volume. Everything you install through the mirror is cached forever.
* `make warmup` pre-downloads ~750 curated packages **plus all their dependencies** (React, Next, Vue, Angular, Express, NestJS, Prisma, Tailwind, Vite, Jest, ESLint, …).
* `make popular` can additionally pull the top-N most-used packages on npm.
* `make export` / `make import` move the whole thing (image + cache) to another machine or a USB drive.

> **Why not "all of npm"?** The full registry is tens of terabytes. A curated + on-demand cache gives you 99% of the benefit at a few GB.

## Requirements

* Docker with Compose v2
* Node.js ≥ 18 + npm (only needed on the host for `warmup`)
* `make`, `bash`, `curl` (Windows: use WSL2 or Git Bash)

## Quick start

```bash
git clone https://github.com/DANIYYL/NpmOfflineMirror.git
cd npm-offline-mirror

make up          # build & start the mirror on http://localhost:4873
make warmup      # (online) cache everything in packages/*.txt  – takes a while
make size        # see how big the cache is
```

Point a project at the mirror:

```bash
make client P=../my-app           # writes ../my-app/.npmrc
# or globally:
bash scripts/use-registry.sh --global
```

From now on `npm install <anything>` works through the mirror. Anything not cached yet is fetched from npmjs **and cached** while you are online.

## Package lists

| File | Contents |
|---|---|
| `packages/frontend.txt` | React/Vue/Angular/Svelte/Next/Nuxt, state, forms, UI kits, charts, editors… |
| `packages/backend.txt` | Express/Fastify/NestJS/Koa/Hono, auth, ORMs/DB drivers, queues, cloud SDKs, utils… |
| `packages/tooling.txt` | TypeScript, Vite/Webpack/Rollup/esbuild, Babel, ESLint/Prettier, Jest/Vitest/Playwright, `@types/*`… |
| `packages/persian.txt` | *(optional)* Persian/RTL/Jalali helpers – delete if not needed |
| `packages/custom.txt` | **Yours.** Add anything you want cached in advance |
| `packages/popular-auto.txt` | Generated by `make popular N=3000` (git-ignored) |

Format: one name per line, `#` for comments, optional version pin (`react@18.3.1`). Names that don't exist are skipped and listed in `warmup-failed.txt`.

## Before you go offline – checklist

1. `make up && make warmup` (and `make popular && make warmup` if you want the long tail).
2. For every project you will work on: `make warm-project P=../my-app` – caches the **exact** versions from its lockfile.
3. If you use them: `make binaries` (Playwright, Puppeteer, Cypress, Prisma engines – see [limitations](#limitations)).
4. `EXTRA_IMAGES="node:22-alpine postgres:16" make export` – saves the mirror image, its cache and your base images into `dist/`.
5. Optional: `make offline` to switch to pure cache mode (no timeouts waiting for a dead network).

## Moving to another machine / restoring

```bash
# on the new machine (no internet needed)
bash scripts/import.sh          # loads images + restores the cache volume
docker compose up -d --no-build # or: make offline
```

`dist/` is git-ignored because it is several GB. Share it via a USB drive, S3/MinIO, or a GitHub Release asset (2 GB per file limit – split with `split -b 1900m`).

## Using the mirror from Docker builds

```dockerfile
# Dockerfile of YOUR project
RUN npm config set registry http://host.docker.internal:4873/
```

```bash
docker build --add-host=host.docker.internal:host-gateway .   # needed on Linux
```

Or attach your project's compose file to the mirror's network and use `http://npm-registry:4873/`.

## pnpm / Yarn

* **pnpm / Yarn 1**: the same `.npmrc` (`registry=http://localhost:4873/`) works.
* **Yarn Berry**: in `.yarnrc.yml` set `npmRegistryServer: "http://localhost:4873"` and `unsafeHttpWhitelist: ["localhost"]`.

## Commands

| Command | What it does |
|---|---|
| `make up` / `make down` | start / stop the mirror (cache is kept) |
| `make warmup` | cache all `packages/*.txt` |
| `make popular N=3000` | generate a "top N most-used packages" list |
| `make warm-project P=<dir>` | cache a project's lockfile versions |
| `make binaries` | cache Playwright / Puppeteer / Cypress / Prisma binaries |
| `make offline` / `make online` | switch config (no uplink / with uplink) |
| `make export` / `make import` | backup / restore everything via `dist/` |
| `make size` | cache size |
| `make client P=<dir>` | write `.npmrc` into a project |

## Limitations

* **Binaries downloaded outside npm** are *not* cached by the registry: Puppeteer/Playwright browsers, Cypress, Electron, Prisma engines, `node-gyp` headers, and native addons that fetch prebuilds from GitHub (`sqlite3`, `better-sqlite3`, some `bcrypt` versions). Use `make binaries`, back up the cache folders, or prefer pure-JS alternatives (`bcryptjs`, `argon2` prebuilds shipped in the package, etc.).
* Warmup caches the **latest** version of each package. Older versions get cached when you install them through the mirror (or via `make warm-project`).
* Warmup uses `--ignore-scripts --force`: scripts aren't run and optional platform packages for *all* OS/CPU combos are fetched (so the cache works on macOS, Windows and Linux).
* apt/apk/pip/etc. are out of scope (npm only).

## FAQ

**Can I have two separate mirrors (frontend / backend)?**
Yes, but they would duplicate shared dependencies. If you insist, run a second instance with another port and volume:

```yaml
services:
  npm-registry-backend:
    image: npm-offline-mirror:latest
    ports: ["4874:4873"]
    volumes: ["npm-mirror-backend:/verdaccio/storage"]
volumes:
  npm-mirror-backend:
```
then `REGISTRY=http://localhost:4874 bash scripts/warmup.sh packages/backend.txt`.

**Why isn't the cache baked into the image?**
Adding one package would force rebuilding a multi-GB image. A volume is incremental; `make export` still bundles everything for transport.

**Install is slow / hangs offline.**
Run `make offline` – it removes the uplink so Verdaccio answers instantly from cache.
